## 2. 활용 범위

**1) 프로젝트 개발 과정에서의 AI 활용**  
ChatGPT, Claude, Codex, GitHub Copilot을 프로젝트 개발 전반의 보조 도구로 활용하였다.

- **코드 작성 및 수정**: 프론트엔드 UI, 백엔드 API, 데이터 처리 로직 등의 구현 및 수정
- **코드 분석 및 오류 해결**: 기존 코드·데이터 구조 파악, 오류 원인 분석 및 해결 방법 탐색
- **데이터 처리 및 테스트**: 프로그램 데이터 수집·정제, 테스트 코드 작성 및 실행 결과 확인
- **개발 문서 작성**: README, 이슈, PR 등 개발 과정에서 필요한 문서 작성

<br> 

**2) 서비스 기능에서의 AI 활용**  
MOIRA STUDIO에는 생성형 AI와 의미 기반 검색 기술을 프로그램 기획 지원 기능에 적용하였다.

- **유사 프로그램 검색**: 사서가 입력한 조건과 관련성이 높은 기존 도서관 프로그램 사례 탐색
- **기획안 초안 생성**: 검색된 사례와 입력 조건을 바탕으로 프로그램명, 기획 의도, 운영 방식, 회차 구성 등을 생성
- **주민 아이디어 활용**: 주민이 게시한 아이디어를 기획 조건에 반영하여 프로그램 기획에 활용
- **기획안 수정**: 생성된 초안을 사서가 확인하고 필요한 항목을 직접 수정하거나 AI를 통해 다시 작성

생성된 기획안은 사서 및 프로그램 기획자의 아이디어 구체화를 돕기 위한 초안으로 제공하며, 서비스 내에서도 이를 명시하였다.

<br> 

## 3. AI 생성 코드의 검증·수정 방식

### ① 구현 전 요구사항과 수정 범위 구체화

AI가 기존 기능이나 디자인을 불필요하게 변경하는 것을 줄이기 위해, 구현 전에 필요한 기능과 수정 범위를 먼저 정리하였다. 복잡한 UI 수정의 경우 ChatGPT를 활용해 요구사항을 구체적인 프롬프트로 정리한 뒤 Codex나 GitHub Copilot에 전달하는 방식을 활용하였다. 또한, 기존에 정상적으로 동작하는 기능이나 디자인 요소는 유지하도록 조건을 함께 제시하였다.

### ② 생성 결과를 실제 화면과 기능으로 확인

AI가 작성한 코드는 로컬 환경에서 직접 실행하여 결과를 확인하였다. 특히 프론트엔드의 경우 코드 자체의 동작 여부뿐만 아니라 실제 화면의 여백, 정렬, 가독성, 반응형 디자인 등을 PC와 모바일 환경에서 확인하였다. 의도한 디자인과 다르거나 기존 기능에 영향을 주는 부분이 있으면 요구사항을 다시 구체화하여 수정하였다.

### ③ 생성된 코드와 UI 문구 직접 수정

AI가 생성한 코드를 확인한 후 프로젝트의 의도나 기존 구조와 맞지 않는 경우에는 팀원이 직접 수정하였다. 또한 프론트엔드 구현 과정에서 AI가 작성한 버튼명, 안내 문구, 기능 설명 등 사용자에게 직접 노출되는 텍스트도 함께 검토하였다. 서비스의 기능이나 의도를 정확하게 전달하지 못하거나 표현이 부자연스러운 경우에는 개발계획서, 리드미 등을 바탕으로 실제 사용자의 관점에서 내용을 다시 작성하였다. 오류 수정 시에도 AI가 제안한 해결 방법을 그대로 적용하기보다 오류 메시지와 실행 결과를 확인한 후 필요한 부분만 반영하였다.

### ④ 변경 사항 확인 후 반영

수정이 끝난 뒤에는 Git diff를 통해 변경 범위를 확인하고, 로컬 환경에서 주요 기능이 정상적으로 동작하는지 다시 확인한 후 커밋 및 PR을 통해 반영하였다.
