## 2. 활용 범위

**1) 프로젝트 개발 과정에서의 AI 활용**  
ChatGPT, Claude, Codex, GitHub Copilot을 프로젝트 개발 전반의 보조 도구로 활용하였다.

- **코드 작성 및 수정**: 프론트엔드 UI, 백엔드 API, 데이터 처리 로직 등의 구현 및 수정
- **코드 분석 및 오류 해결**: 기존 코드·데이터 구조 파악, 오류 원인 분석 및 해결 방법 탐색
- **데이터 처리 및 테스트**: 프로그램 데이터 수집·정제, 테스트 코드 작성 및 실행 결과 확인
- **개발 문서 작성**: README, 이슈, PR 등 개발 과정에서 필요한 문서 작성

<br> 

**2) 서비스 기능에서의 AI 활용**  
MOIRA STUDIO에는 생성형 AI와 의미 기반 검색 기술을 프로그램 기획 지원 기능에 적용하였다.

- **유사 프로그램 검색**: 사서가 입력한 조건과 관련성이 높은 기존 도서관 프로그램 사례 탐색
- **기획안 초안 생성**: 검색된 사례와 입력 조건을 바탕으로 프로그램명, 기획 의도, 운영 방식, 회차 구성 등을 생성
- **주민 아이디어 활용**: 주민이 게시한 아이디어를 기획 조건에 반영하여 프로그램 기획에 활용
- **기획안 수정**: 생성된 초안을 사서가 확인하고 필요한 항목을 직접 수정하거나 AI를 통해 다시 작성

생성된 기획안은 사서 및 프로그램 기획자의 아이디어 구체화를 돕기 위한 초안으로 제공하며, 서비스 내에서도 이를 명시하였다.

<br> 

## 3. AI 생성 코드의 검증·수정 방식

### ① 구현 전 요구사항과 수정 범위 구체화

개발계획서를 바탕으로 기능별 이슈를 작성하고, 이를 개발 과정의 지침으로 활용하였다. 이슈 문서 작성에는 AI를 활용하되 필요한 기능과 수정 범위가 적절한지는 팀원이 다시 검토하였다. 또한 페이지별 UI가 일관된 기준으로 구현될 수 있도록 공통 디자인 원칙을 `Design.md`로 정리하고, AI가 프론트엔드 코드를 생성하거나 수정할 때 이를 참고하도록 하였다. 복잡한 UI 수정의 경우 ChatGPT로 요구사항을 구체적인 프롬프트로 정리한 뒤 Codex나 GitHub Copilot에 전달하고, 기존 기능이나 디자인 요소를 불필요하게 변경하지 않도록 조건을 함께 제시하였다.

### ② 단계별 구현 결과 확인 및 수정

하나의 기능을 구현할 때 작업을 주요 커밋 단위로 나누고, 각 단계에서 AI가 수행한 작업과 변경 사항을 확인하였다. 프론트엔드는 생성된 코드를 로컬 환경에서 실행하여 기능뿐만 아니라 PC·모바일 화면의 레이아웃과 반응형 동작을 확인하였다. AI가 작성한 버튼명, 안내 문구 등 사용자에게 노출되는 텍스트도 개발계획서와 README를 기준으로 검토하고 부자연스럽거나 서비스의 의도와 맞지 않는 표현은 직접 수정하였다.

### ③ 데이터 처리 및 AI 기능 검증

OCR을 활용한 첨부파일 처리는 `dry-run → 표본 1건 → 일부 데이터 적용 → 전체 처리` 순으로 범위를 넓히며 결과를 확인하였다. 각 단계에서 실제 원문과 추출 결과를 사람이 직접 비교하고, 전체 처리 이후에도 일부 불일치 사례를 다시 검토하였다.

유사도 검색은 우선 AI를 통해 여러 자연어 질의를 생성하고 생성된 자연어를 입력하여 TOP 5 검색 결과가 실제 질의와 관련 있는지 AI와 팀원이 함께 확인하였다. 검색 결과가 적절하지 않은 사례는 원인을 확인하고 검색 필터링 방식을 적절히 조정하였다. 크롤링 이후 정제한 프로그램 데이터 역시 일부 결과 우선적으로 확인하여 데이터가 의도한 형태로 처리되었는지 AI와 사람이 직접 검증하였다.

### ④ 최종 검토 및 반영

기능 구현이 끝난 후에는 Git diff를 통해 최종 변경 범위를 확인하고 각 팀원의 로컬 환경에서 주요 기능을 실행하였다. 이후 PR을 통해 팀원의 리뷰와 피드백을 반영하고, 수정이 완료된 기능만 main 브랜치에 병합하였다.
