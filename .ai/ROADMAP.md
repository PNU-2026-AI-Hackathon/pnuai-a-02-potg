# 모이라 개발 로드맵

이 문서는 모이라가 지금까지 진행한 개발 순서와 앞으로의 목표를 함께 관리한다. `CURRENT_SCOPE.md`가 **지금의 범위**를 정의한다면, 이 문서는 **완료한 기반과 앞으로의 진행 순서**를 설명한다.

아래 버전은 Git 릴리스 태그가 아니라 프로젝트의 개발 단계를 구분하기 위한 문서상 버전이다. 일정과 우선순위가 변경되면 관련 Issue/PR과 함께 갱신한다.

## 단계 요약

| 단계 | 상태 | 핵심 목표 |
|---|---|---|
| v0.1 | 완료 | 저장소 기반, 홈 화면, Frontend·Backend 골격 |
| v0.2 | 완료 | 로그인, 회원가입, 관심분야와 사용자 DB 연동 |
| v0.3 | 진행 예정 | 메인 페이지 개선, `/community/*` 게시판 DB 연동 |
| v0.4 | 계획 | 지역 제안과 AI 의제 분석 |
| v0.5 | 계획 | 모이라 스튜디오 |
| v0.6 | 계획 | 프로그램 관리와 주민 참여 흐름 완성 |

## v0.1 — 프로젝트 기반과 서비스 골격

**상태: 완료**

### 목표

- 저장소와 협업 기반 구성
- Next.js Frontend 골격 구축
- Express Backend 및 mock API 구축
- 메인 화면과 Backend summary·공지 연동

### 완료된 주요 작업

- 프로젝트 디렉터리와 기여 가이드 구성
- GitHub Issue 및 PR 템플릿 추가
- 홈 화면 스켈레톤 UI 구현
- Express Backend skeleton과 mock API 구현
- 메인 페이지의 summary 및 announcements 연동

## v0.2 — 사용자 인증과 관심분야

**상태: 완료된 코드 경로 존재, 실행 검증 필요**

### 목표

- 로그인과 세션 유지
- 단계형 회원가입
- 사용자 및 관심분야 PostgreSQL 저장

### 완료된 주요 작업

- JWT 로그인 API와 로그인 UI 연동
- RDS PostgreSQL 기반 사용자 인증 코드 구현
- Next.js HTTP-only 쿠키 기반 세션 유지와 로그아웃
- 단계형 회원가입 및 관심분야 선택 UI
- Prisma `User`, `Interest`, `UserInterest` 모델과 마이그레이션
- 회원가입 및 사용자 관심분야 API 연동

실제 빌드, DB 연결 및 API 실행 검증 완료를 의미하지 않는다. 상세 상태는 `IMPLEMENTATION_STATUS.md`를 따른다.

## v0.3 — 커뮤니티 게시판 기반 완성

**상태: 진행 예정**

### 목표

1. 메인 페이지 정보 구조와 커뮤니티 연결 개선
2. `/community/*` 공통 게시판 데이터 모델 설계
3. 게시글 Prisma 모델과 마이그레이션 추가
4. 게시글 목록·상세·작성·수정·삭제 API 구현
5. 인증 및 역할별 권한 정책 연결
6. 정적 커뮤니티 데이터를 DB 데이터로 전환

### 현재 기반

- 작은도서관 행사 및 소식 UI 골격
- 자유게시판 UI 골격
- 지역 제안 게시판 UI 골격
- 공통 게시판 데이터 모델과 목록 UI

### 정리 대상

- `/board`와 `/api/posts`는 레거시로 유지한다.
- `/community/*` DB 연동 후 통합 또는 제거 범위를 별도 이슈에서 결정한다.

## MVP 제외 및 별도 결정 대상

- 대학생 봉사자 모집 및 매칭은 현재 MVP에서 제외한다.
- 남아 있는 volunteer API, mock 데이터, summary 항목은 과거 계획의 잔여 코드다.
- 제거 여부는 별도 이슈에서 결정한다.
- GitHub Actions, `npm run check`, AI 자동화 스크립트 등 개발 자동화는 기능 로드맵과 분리된 별도 PR로 진행한다.

## 갱신 규칙

- 단계가 시작되면 상태를 변경하고 관련 Issue/PR을 연결한다.
- 완료 조건을 충족하지 않은 단계를 완료로 표시하지 않는다.
- 현재 개발 우선순위가 바뀌면 `CURRENT_SCOPE.md`도 함께 수정한다.
- 기술 또는 제품 방향 결정이 생기면 `DECISIONS.md`에 결정·이유·영향을 기록한다.
- 실제 구현이 바뀌면 `IMPLEMENTATION_STATUS.md`를 갱신한다.
